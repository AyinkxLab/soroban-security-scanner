# SS-007 — Hardcoded Stellar account or contract address

- **Severity:** medium
- **Confidence:** low
- **Category:** configuration

## Problem

A string literal matches the shape of a Stellar account (`G...`) or contract
(`C...`) address. Hardcoding an address bakes a fixed counterparty or
administrator into the contract, preventing rotation and making the contract
unsafe if that key or contract changes or is compromised. Addresses are public,
so this is a design concern rather than a secret leak.

## How it is detected

Scans string literals in confirmed Soroban source for Stellar strkey shape:
exactly 56 characters, starting with `G` or `C`, with the remaining characters
in base32 (`A`–`Z`, `2`–`7`).

## Limitations

- Shape matching only; does not validate the strkey checksum.
- Cannot tell an intentional constant from an accidental one.

## False positives

- Well-documented, intentional constants with a rotation plan.
- Test or documentation strings that resemble addresses.

## Remediation

Store addresses in contract storage or pass them as parameters, validating
against stored configuration. If a compile-time constant is required, document
the rotation and key-compromise plan.
