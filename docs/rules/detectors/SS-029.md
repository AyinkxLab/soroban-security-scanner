# SS-029 — Public test or debug hook in a contract entry point

- **Severity:** medium
- **Confidence:** medium
- **Category:** access-control

## Problem

A public contract entry point is named like a test or debug backdoor (a `test`,
`debug`, `dev`, `mock`, or `dummy` name segment). Backdoor entry points that
remain callable in a production deployment let anyone invoke privileged behavior,
and are a well-known way on-chain contracts are compromised.

## How it is detected

For every public function inside a `#[contractimpl]` block, the function name is
split on `_` and each segment is compared against a small list of test/debug
segments. Matching is segment-based, so ordinary names that merely contain a
substring (for example `latest`) are not flagged.

## Limitations

- Purely name-based; it does not inspect what the function actually does.
- A function may be named `..._dev` yet be perfectly safe, or vice versa.

## False positives

- Production functions that legitimately contain a listed segment (for example a
  `development` segment used for unrelated meaning).
- Test-only code that is already excluded by `#[cfg(test)]` (it is still a
  contract entry point only if it compiles into the contract impl).

## Remediation

Remove test/debug entry points before deployment, or gate them behind
`#[cfg(test)]` or a compile-time feature so they cannot be called from a
production build. Never ship a privileged function intended only for testing.
