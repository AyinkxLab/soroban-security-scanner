# SS-003 — Unbounded storage iteration in an entry point

- **Severity:** medium
- **Confidence:** low
- **Category:** resource-usage

## Problem

A contract entry point iterates over storage. If the iterated collection grows
without bound, resource cost grows with it and may exceed Soroban's ledger
entry, CPU, or memory limits, causing the entry point to fail (a denial of
service).

## How it is detected

Reports calls named `iter`, `keys`, or `values` whose receiver expression
mentions `storage`, inside a public `#[contractimpl]` function.

## Limitations

- Heuristic; cannot prove the collection is unbounded.
- Does not measure actual resource usage.
- Bounded loops over storage are reported even when a limit is enforced.

## False positives

- Loops over small, contract-controlled collections.
- Paginated reads that limit the number of processed entries.

## Remediation

Bound the amount of work per invocation: paginate with an explicit limit,
maintain aggregate values instead of scanning, or cap entries processed and
return partial results.
